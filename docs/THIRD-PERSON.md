# 3인칭 3D 프로토타입 · 0.2

현재 기본 화면은 **실제 Three.js WebGL**이다. 화면에 보이는 캐릭터를 직접 움직이며, 뒤를 따라가는 카메라로 골목을 탐색한다. 기존 6장 이벤트·HP·허기·아이템·저장은 같은 도메인 엔진을 사용한다. 대규모 도시·전투·차량 운전을 갖춘 GTA 완성작을 의미하지는 않는다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD / 방향키 | 카메라 기준 이동, 대각선 속도 정규화 |
| 화면 드래그 | 인물 주변으로 시점 회전, 수직 각도 제한 |
| Shift 누르기 | 달리기 |
| C | 은신 전환 |
| E / 화면의 조사 버튼 | 가까운 물체의 선택지 열기 |
| I / 가방 버튼 | 회복 물품 사용 |
| Escape / 돌아가기 | 열린 패널 닫기 |
| 대사 버튼 | 전체 내러티브 본문 표시 |
| 텍스트 모드 버튼 | 기존 SVG·HTML 방식으로 전환 |

모바일에는 방향 패드, 달리기·은신 버튼과 화면 드래그 시점 조작이 있다. 대화상자·가방·선택지가 열린 동안 이동은 멈춘다. WebGL을 지원하지 않거나 캐릭터 로딩에 실패하면 설명과 함께 텍스트 모드로 돌아간다.

## 모델링 개선

캐릭터는 Blender 4.3에서 직접 제작한 원본 모델이며 외부 인물 에셋을 내려받지 않는다.

- `assets/civilian.blend`: 편집 가능한 메시·재질·뼈대·애니메이션 원본.
- `assets/civilian.glb`: 브라우저에서 사용하는 glTF 2.0 바이너리.
- `scripts/create-character.py`: 모델과 리그를 재생성하는 Blender 스크립트.
- 17개 본과 정규화된 스킨 가중치. 팔꿈치·무릎 주변은 연속 메시로 휘어져 움직일 때 부품이 떨어져 보이지 않는다.
- 얼굴의 턱·코·눈꺼풀·눈썹, 빗어 넘긴 머리카락, 손가락, 재킷의 깃·포켓·소매 주름·지퍼, 바지 주름과 부츠, 배낭의 롤톱·버클·파이핑·어깨끈을 모델링했다.
- `Idle`, `Walk`, `Run`, `Sneak` 4개 클립을 AnimationMixer로 전환한다. NPC는 뼈대를 복제하고 재질을 개별화해 같은 메시를 재사용한다.

원본 재생성은 선택 작업이며 일반 설치·실행에 Blender가 필요하지 않다.

```sh
BLENDER_USER_CONFIG=/tmp/exit-north-blender-config blender --background --threads 2 --python scripts/create-character.py
npm run build
```

이 환경의 Blender는 선택적인 Draco 압축 라이브러리가 없어 관련 진단을 출력하지만, 압축되지 않은 GLB를 정상 생성한다. 모델은 Draco 디코더나 외부 텍스처가 필요 없다. 결과의 스켈레톤·클립·스킨 가중치를 테스트에서 직접 검사한다.

## 공간과 카메라

`data/spaces.json`이 12개 공간의 테마·스폰·경계·조명·안개·카메라 거리·상호작용 대상과 이벤트 연결을 선언한다. `schemas/spaces.schema.json`으로 검증하고, 모든 이벤트 선택지가 실제 핫스폿에 연결되었는지 확인한다.

현재 모든 노드의 `camera_mode`는 사용자가 요청한 `third_person_follow`다. 인물 오른쪽 어깨 뒤의 카메라가 부드럽게 따라가고, 건물과 겹치는 경우 시점 거리를 줄인다. 장면별 다른 시점 프리셋은 [3D 확장 가이드](3D-EXTENSION.md)에 후속 설계로 남아 있다.

| 공간 | 시각 구성 |
|---|---|
| 집 앞 골목 | 생활감 있는 건물·전선·가로등·나무·차량·행인과 1장 수색 사물 |
| 교화소 야드·통로 | 낮은 작업 건물·철책·감시탑·움직이는 빛·배급 상자 |
| 얼어붙은 강·쉼터 | 차가운 안개·빙면 균열·바위·나무·안내인·보급 상자 |
| 도시·찻집·도로 | 네온 간판·하역 장소·식료품·소개자·차량 |
| 숲·마지막 강 | 나무·덤불·보급품과 갈림길 |
| 철문·에필로그 | 철문과 보호 요청 표식, 따뜻한 정착 장면 |

공간은 절차적으로 제작한 스타일화된 스테이지다. 1장의 수색 사물은 집 앞 골목의 탐색 시연으로 배치했다. 실물 주택 내부, 교화소·지리의 고증, 연속된 대규모 월드나 사실적인 수면 물리까지 구현한 것은 아니다. 캐릭터가 목표에 접근하면 E 안내가 나타나고, 해당 사물에 연결된 선택지만 표시한다. 조사 완료한 일회성 목표는 표식이 사라진다.

## 이동도 생존 행동

`world.rules.movement`가 이동 2m 구간의 선행 비용을 선언한다.

| 방식 | 속도 | 2m 구간의 비용 |
|---|---:|---|
| 걷기 | 2.3m/s | HP −1 · 허기 +1 |
| 달리기 | 4.7m/s | HP −3 · 허기 +1 |
| 은신 | 1.15m/s | HP −1 · 허기 +3 |

렌더러는 실제로 이동할 수 있는지 먼저 검사한다. 벽에 막혔다면 비용을 부과하지 않는다. 구간 비용이 필요할 때 `{type:'TRAVEL', mode:'walk'}`를 기존 GameStore에 보내고, 비용·아사 피해를 버틴 경우에만 이동한다. 사망한 뒤 마지막 한 걸음을 무료로 움직이지 않는다.

지불한 거리의 잔량은 물리 이동에서 차감하는 내부 계산값이며 AP나 사용자가 충전하는 자원이 아니다. 이동 방식을 바꾸면 새 방식의 구간 비용을 먼저 낸다. 중도에 멈춰도 이미 낸 비용은 환불하지 않는다. 실제 거리와 구간 지불로 판정하므로 렌더링 프레임 횟수로 생존 비용을 중복 부과하지 않는다.

현재 공간 좌표와 카메라는 저장하지 않는다. 새로고침하면 해당 스테이지의 진입 위치에서 재개하고, HP·허기·아이템·단서·이벤트 진행·난수 상태는 유지한다. 지불한 거리 잔량은 재생성하지 않으므로 새로고침으로 무료 이동 비용을 만들 수 없다.

## 단일 파일과 배포

`npm run build`가 Three.js·GLTFLoader·모델 바이너리·JSON·CSS·게임 코드를 `index.html`에 포함한다. 런타임 CDN, 모델 URL, API 키, 외부 텍스처 요청이 없다. 빌드는 esbuild와 고정한 npm 의존성을 사용한다. Three.js의 라이선스는 `THIRD_PARTY_NOTICES.md`와 생성 HTML에 포함한다.

현재 Node 서버는 기존 3000번 포트에서 새 생성물을 제공한다. 요청한 Sites 플러그인은 현재 세션의 도구·스킬 목록에서 게시 기능이 검색되지 않아 실행하지 못했다. Sites에 게시되었다거나 공개 URL이 있다고 주장하지 않는다. 게시 도구가 연결되면 이 단일 HTML을 업로드하고, 실제 URL에서 WebGL·모바일·저장·입력을 다시 확인해야 한다.

## 검증 범위

엔진·충돌 수학·공간 스키마·GLB 구조 검증 외에 실제 Chromium에서 WebGL 렌더링, 캐릭터 이동·시점 회전, E 조사, 이동 비용, 벽 충돌, 패널 중 이동 정지, 모바일 방향 패드, 6장 장면 전환, 사망 전 이동 중단, WebGL 미지원 폴백을 검사한다.

이 환경에서는 SwiftShader 소프트웨어 렌더링을 사용한다. 실제 모바일 GPU·Safari·특정 하드웨어의 프레임 속도는 검증하지 않았으며 고정 FPS를 보장하지 않는다. 모델과 3D 배경은 실제 3D지만 전체 공간은 프로토타입 범위다.
